## 1. 启动与测试素材

在 `huiye-ppt` 目录执行：

```powershell
npm run dev:ui
```

打开终端显示的 `http://127.0.0.1:5174/`，确认界面标注“本地演示”。使用同一浏览器、同一主机名及端口检查刷新恢复；浏览器按来源隔离 localStorage 和 IndexedDB。

已有工作稿时，启动先显示选择页；点击“继续上次草稿”才进入原阶段。若要保留正在编辑的稿件，继续后先下载草稿备份，再打开示例。App 只自动保存当前工作稿。

仓库中有两张适合测试的素材：

| 文件 | 用途 | 验收重点 |
|---|---|---|
| `public/examples/coffee-takeaway.jpg` | 外带咖啡场景照片，1600×1067 | 完整显示、居中铺满、左右交换 |
| `public/examples/coffee-waiting-time.png` | 等待时长对比图，1400×900 | 透明/实色边缘、文字清晰度、数值和图表边界完整 |

来源、许可与示例声明见 [图片来源说明](../public/examples/SOURCES.txt)。门店、人物和数据均为虚构；咖啡照片只作场景示意，不是该门店的现场记录。图表由程序绘制，未调用 AI 生图。

## 2. 先检查新示例

1. 点击顶部“打开示例”，打开“南桥咖啡午高峰外带流程复盘”；已有稿件时先确认替换。该入口在本地演示与 Anna 中均显示。
2. 检查材料包含明确的问题、观察口径、试点动作、结果和下周安排，而不只是笼统的知识管理描述。
3. 核对关键数字：等待时长中位数为 7.2 分钟和 4.8 分钟，记录订单为 420 单和 438 单，超过 10 分钟的订单为 74 单和 29 单。
4. 检查场景图和图表进入对应图文页面，标题与正文仍可编辑。
5. 逐页查看文字密度和配图清晰度。图表默认使用“完整显示”；其中的数值、类别和边缘说明不能因自动裁剪而消失。

“使用示例材料”只填入材料表单；“打开示例”进入固定成稿；编辑器右侧“页面图片 → 示例图片”只给当前页添加照片或图表。示例的虚构标识应保留，不把固定文稿显示成真实 AI 生成结果。在 Anna 中点击“生成大纲”或“生成幻灯片”会调用真实模型，检查示例图片时不需要这些操作。

## 3. 上传、替换、移除和排版

| 操作 | 预期结果 |
|---|---|
| 在普通文字页上传咖啡照片 | 上传成功后切换为图文版式，文字保留；画布与缩略图显示图片 |
| 点击右侧“示例图片”，选择照片或图表 | 只更新当前页配图，正文保留；同样经过图片处理与持久化，可撤销重做 |
| 关闭示例图片弹窗而未选择 | 当前稿不变；保存图片期间重复点击或关闭不能中断为半完成状态 |
| 取消系统文件选择框 | 当前图片和文稿不变，没有新增历史或用量 |
| 切换图片在左/右 | 图片与正文交换位置，标题和核心信息保持在上方 |
| 选择“完整显示” | 图片按原比例完整进入区域，可留边；咖啡杯或图表不被拉伸 |
| 选择“铺满” | 图片居中裁剪以填满区域，不发生横向或纵向拉伸 |
| 替换为等待时长图 | 仅当前页的图片改变，文字保持；可切回完整显示检查图表 |
| 移除图片 | 清除当前页关联，显示缺图状态；不静默导出一页缺图 PPTX |
| 切换回要点等文字版式 | 画布隐藏图片；切回图文后仍可使用原关联图片 |
| 上传有效 WebP | 本地处理为可导出的 PNG/JPEG；无需网络服务 |
| 上传 SVG、伪造后缀文件、空文件或损坏图片 | 明确报错，不覆盖当前成功图片，不产生模型调用 |

输入图片上限为 10 MiB、2400 万像素；本地处理后最长边不超过 1920 像素，单张资产不超过 1 MiB。PNG/WebP 保留透明通道；JPEG 保持 JPEG。文件实际格式和尺寸需要检查，不能仅相信文件扩展名。

图文页适合少量文字。长内容应提示精简或拆页，不能为了导出成功而截掉正文。预览和导出均使用同一份排版几何。

## 4. 撤销重做与复制隔离

以下操作都在本次打开期间完成，避免刷新清空内存中的历史：

1. 上传照片 A，再替换为图片 B。
2. 点击撤销，确认照片 A 恢复；重做后恢复图片 B。
3. 移除图片，再撤销与重做，确认图片能恢复而非变成坏图。
4. 切换左右位置或显示方式，分别撤销、重做，检查画布和控件同步。
5. 复制这页，只替换副本图片；返回原页，确认原图、文字、显示方式均未被改动。
6. 删除副本，再撤销，确认副本的图片和文字一起恢复。
7. 撤销一次后进行新编辑，确认旧重做分支被清除。
8. 用 `Ctrl+Z` / `Ctrl+Y` 复验；macOS 使用 `Cmd+Z` / `Cmd+Shift+Z`。

复制页复用不可变图片资产，而不是重新上传同一文件。替换或移除只改变页面引用；旧资产暂时保留，避免历史记录还需要它时已被删除。历史仍为当前页面会话内的最近 50 步，刷新后重置；已经消耗的 AI 用量不随撤销回退。

## 5. 自动保存与刷新恢复

1. 给一页添加图片，改为图片在右、完整显示，并编辑正文。
2. 选择非第一页，等待界面显示“已保存到本机”后刷新。
3. 先看到上次草稿卡，点击“继续上次草稿”；确认工作阶段、选中页、文字、图片、左右位置和显示方式均恢复。
4. 再次打开这个本地地址并点击继续，确认图片从本地持久存储恢复，而不是依赖尚未失效的内存 Blob URL。
5. 返回材料阶段输入未完成材料，等待保存后刷新并点击继续；确认材料阶段恢复，已保存成稿及图片仍能从编辑阶段访问。

本地图片字节放在 **IndexedDB**，JSON 草稿只保存图片资产引用和元数据。清除站点数据、换浏览器、换主机名或端口会进入另一份存储；跨存储迁移应使用带图 ZIP 备份。

读取图片失败时应显示明确提示，保留文字和引用，并阻止缺图导出。不要把加载失败自动当作用户移除了图片。

## 6. PPTX 导出

1. 保留照片页与图表页，分别选择完整显示和铺满；至少有一页将图片放在右侧。
2. 导出 PPTX，确认下载成功且页数与当前文稿一致。
3. 在 PowerPoint/WPS 中检查标题、正文、图片位置、比例和裁剪，尤其确认图表的 7.2 / 4.8 数值清晰可读。
4. 单独选中图片，确认它是图片对象；单独编辑正文，确认文字没有被整页截图替代。
5. 检查演讲备注及材料引用仍保留，幻灯片画布仍不出现来源与版式角落标签。
6. 移除某个图文页的图片后尝试导出，应明确要求补图或换版式，不生成缺图文稿。

导出文件总大小上限为 20 MiB。图片以实际字节嵌入 PPTX，不依赖临时外链；已下载的 PPTX 应能在离线环境显示图片。浏览器预览与压缩包检查不能替代 PowerPoint/WPS 的逐页视觉验收。

## 7. ZIP 带图备份与跨存储导入

1. 下载带图草稿备份，文件应为 `.huiye.zip`，包含文稿 JSON 和所需图片资产。
2. 在另一个浏览器或另一独立本地端口打开 App，确认该来源没有刚才的工作稿。例如新终端执行：

   ```powershell
   npm run dev:ui -- --port 5177
   ```

3. 点击顶部“导入汇页草稿”，选择整个 `.huiye.zip`，无需解压。点击弹窗“导入并继续”后，应恢复图片和正文，不需要先手动上传图片，也不依赖原浏览器的 IndexedDB。
4. 等待保存，刷新新来源并点击“继续上次草稿”，确认图片仍可见。
5. 在新来源导出 PPTX，确认图片已嵌入。
6. 导入旧版纯文字 `.huiye.json`，检查兼容性；旧稿不应因为没有图片字段而失效。
7. 对缺失图片、损坏 ZIP、异常路径或超大备份显示错误，保留当前工作稿。

导入备份会替换当前工作稿并重置历史，图片应先完成本地持久化，再切换当前文稿。ZIP 是携带图片的可迁移备份；单独的文件路径或临时访问地址无法完成跨浏览器恢复。

## 8. 架构与后续平台验收边界

| 环节 | 本地演示 | Anna 环境 |
|---|---|---|
| 图片选择和压缩 | 浏览器本地处理 | 浏览器本地处理 |
| 图片字节 | IndexedDB | `files.upload_init` → 签名 PUT → `files.upload_finalize` |
| 草稿文字与图片引用 | localStorage | App 自有作用域的 `storage.set` |
| 重新打开图片 | 从 IndexedDB 读取 | `files.download_url` 重签后读取 Blob |
| 图文预览 | SVG 图片＋独立文字 | 同一前端渲染逻辑 |
| PPTX | 原生图片对象＋可编辑文字 | 同一构建逻辑，再由宿主提供下载 |

这条路径不需要 Executa、自建服务器或模型调用。图片占文件存储空间；没有自动执行网络搜图或 AI 生图。JSON 不保存图片 Base64 或临时签名 URL。

本轮先完成本地验收。Anna staging 的真实文件上传、签名地址刷新、R2 CORS/CSP、跨设备恢复、平台存储限额和宿主下载需要后续单独验证，不能由本地 IndexedDB 或模拟 Host API 测试替代。

本地检查命令：

```powershell
npm test
npm run build
npm run validate
```

复验时以当前命令日志为准；上述记录只对应本批次实际完成的检查范围。
